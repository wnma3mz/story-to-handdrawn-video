## 1. 目标与边界

输入一本小说和项目配置，输出可复制到另一台电脑继续生成视频的完整生产包。

本流程负责：故事骨架、改编策略、逐集剧本、导演规划、全局资产登记、资产参考图、分镜表、分镜面板和视频任务清单。

本流程不负责：镜头视频生成、配音、音乐、剪辑和最终成片。

禁止为同一阶段建立多个“最终版”“最新版”。修订直接更新唯一产物，并在状态文件记录原因。

## 3. 阶段状态

每个阶段只能取以下状态：

- `NOT_STARTED`：尚未开始。
- `IN_PROGRESS`：当前 Agent 正在处理。
- `REVIEW`：产物完成，等待审核。
- `APPROVED`：审核通过，锁定为下游输入。
- `BLOCKED`：缺少必要输入，必须在状态文件写明阻断原因。

同一时刻最多一个阶段为 `IN_PROGRESS`。只有直接上游全部 `APPROVED` 才能启动下一阶段。

## 4. S0-S8 执行契约

### S0 项目建档

- 输入：小说全文、集数、单集时长、画幅、题材、画风、外部视频平台信息。
- 执行：填写项目配置；复制状态模板；确认小说文件可完整读取。
- 通过条件：关键配置无空项；原著范围和目标集数明确。

### S1 故事骨架

- 必读：`skills/script_execution_skeleton.md`、选定题材的 `README.md`。
- 输入：原著全文、项目配置。
- 输出：故事核、人物小传、三幕、逐集分集、钩子、反转登记表。
- 通过条件：每集有独立戏剧目标与集末钩子；全剧能覆盖原著核心因果。

### S2 改编策略

- 必读：`skills/script_execution_adaptation.md`。
- 输入：原著全文、已批准故事骨架。
- 输出：保留、合并、删除、前置、后置决策及世界观呈现办法。
- 通过条件：每个重大改动能追溯到原著和骨架；不擅改故事核心。

### S3 分集剧本

- 必读：`skills/script_execution_script.md`、题材技法。
- 输入：已批准骨架、策略、目标集号、上一集结尾与下一集钩子。
- 输出：每集一份剧本。
- 执行顺序：EP01→最终集，不得并行跳写后续集。
- 通过条件：单集时长匹配配置；开头承接上集；结尾兑现骨架钩子；人物关系连续。
- 锁定：批准后建立台词基线，下游不得改写、删减或合并台词。

### S4 导演规划

- 必读：`skills/production_execution_director_plan.md`、选定题材与画风的导演技法。
- 输入：全部已批准剧本。
- 输出：每集一份导演规划。
- 通过条件：场次覆盖剧本；参演角色齐全；每场有目标、情绪推进和镜头节奏。

### S5 全局资产

- 必读：`skills/production_execution_derive_assets.md`、画风下的角色/道具/场景提示词规范。
- 输入：全部剧本和导演规划。
- 输出：一份全局资产登记、一份全局资产提示词、每个资产一张参考图。
- 规则：先合并同一实体，再创建衍生态；同一角色不得因换集重复建号。
- 编号：角色 `101-199`，道具 `201-299`，场景 `301-399`；衍生态用 `父ID-后缀`。
- 通过条件：每个后续引用 ID 都存在；每个登记资产都有对应本地图片；文件名前缀等于资产 ID。

### S6 分镜表

- 必读：`skills/production_execution_storyboard_table.md`、分镜表题材/画风技法。
- 输入：单集剧本、导演规划、全局资产登记。
- 输出：每集一份分镜表。
- 通过条件：场次和台词覆盖 100%；单镜不超过 10 秒；每个镜头引用合法资产；禁 BGM；禁光影色调词。

### S7 分镜面板

- 必读：`skills/production_execution_storyboard_panel.md`、`skills/production_skills/storyboard_prompt_techniques.md`。
- 输入：分镜表、全局资产登记、参考图索引。
- 输出：每集一份分镜面板。
- 通过条件：一镜对应一个 track；track 在全剧范围唯一；`associateAssetsIds` 与画面一致；提示词描述首帧；无台词、音效、光影色调词混入出图正文。

### S8 迁移交付

- 输入：S0-S7 全部批准产物。
- 输出：视频任务清单、跨电脑执行说明和验收报告。
- 视频任务清单按集索引到逐镜分镜面板；每个面板逐镜列出全局 track、时长、参考图文件、首帧提示词和视频动作描述，台词与音效由同号分镜表提供，避免复制后产生两个不一致版本。
- 通过条件：复制整个项目目录后，不依赖原电脑绝对路径；无缺图、无空提示词、无重复 track、无悬空资产 ID。

## 5. 全局一致性规则

1. 项目配置、故事骨架、改编策略是全剧上游，不按集复制出多个版本。
2. 全剧只维护一份资产登记表。
3. 角色身份、外貌和基础服装以角色参考图为准；衍生造型必须引用父 ID。
4. 同一场景不同时间或天气建立衍生场景，不重新设计空间布局。
5. 每集剧本开头必须检查上一集结尾状态；结尾必须记录人物、道具和秘密状态供下一集继承。
6. track 从 EP01 的 001 开始全剧连续递增，不按集重置。
7. 文件中只使用项目相对路径，方便跨电脑迁移。

## 6. 审核与返工

每阶段先由执行 Agent 自审，再由接手 Agent 或同一 Agent以监督规则复核。审核报告只列问题，不静默修改已批准上游。

- A：无严重问题，可批准。
- B：无严重问题，轻微修订后批准。
- C：存在 1-2 个严重问题，返工后重审。
- D：存在 3 个以上严重问题，阶段重做。

修改上游后，状态文件必须把所有受影响下游阶段回退为 `NOT_STARTED`，并删除“已批准”标记，但保留文件供对照。

## 7. 跨 Agent 交接

交出前填写 `Agent交接单.md`：

- 当前唯一进行中阶段。
- 已批准输入文件。
- 本轮新增或修改文件。
- 未决问题和不能自行假设的事项。
- 下一位 Agent 的第一项可执行动作。

接手 Agent 必须先核对目录、状态和交接单，再开始工作；聊天内容只能作为辅助，不得覆盖文件记录。

## 8. 完成定义

不得以“已跑通一个样例”代表整部完成。只有同时满足以下条件才可宣布完成：

- S0-S8 全为 `APPROVED`。
- 目标集数对应的剧本、导演规划、分镜表、分镜面板数量完全一致。
- 所有资产引用均能解析到登记项和本地参考图。
- 全剧 track 唯一连续。
- 台词从剧本到视频任务清单逐字一致。
- 交付包使用相对路径，可整体复制到另一台电脑。
