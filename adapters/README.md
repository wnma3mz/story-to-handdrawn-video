# adapters/ — 上游内容层与渲染器之间的编译层

上游 `content/` 产出的是**给人看的 Markdown**，渲染器只认 `storyboard.json`。
本目录是两者之间唯一的转换点。所有映射规则都写在这里，不散落在别处。

```
content/skills/*.md  产出的 Markdown
        │
        │  panel_parser.py        ← 唯一解析入口
        ▼
   PanelShot / AssetRegistry / ScriptDoc
        │
        ├─→ compile_storyboard.py   storyboard.json      （渲染器输入）
        ├─→ compile_image_jobs.py   codex-image-jobs.json（出图依赖图）
        └─→ compile_narration.py    voiceover.json       （配音输入）
                                        │
                              verify_lock.py ← 交给渲染器前复查红线
```

## 为什么必须有这一层

三个上游项目的中间产物格式互不相同，而渲染器的输入格式是封闭的：

| 上游 | 中间产物 | 渲染器需要 |
|---|---|---|
| content/ | `07_分镜面板_EPxx.md` | `storyboard.json` |
| content/ | `05_资产提示词.md` | `codex-image-jobs.json` |
| content/ | `03_剧本_EPxx.md` | `voiceover.json` 的 `speech_text` |

没有这一层就只能人工誊抄，而誊抄必然破坏台词锁——上游红线 1 要求台词逐字一致。

## 文件

| 文件 | 职责 |
|---|---|
| `panel_parser.py` | 解析上游三份 Markdown，产出 dataclass。其余模块只依赖它 |
| `motion_map.json` | 景别与运镜词表 → 渲染器运动词汇；取景框按画幅查表 |
| `compile_storyboard.py` | 分镜面板 → `storyboard.json` |
| `compile_image_jobs.py` | 资产登记 + 资产提示词 + 分镜面板 → `codex-image-jobs.json` |
| `compile_narration.py` | `storyboard.json` → `voiceover.json`，**按场边界分组** |
| `verify_lock.py` | 十条红线的机器校验，交给渲染器前跑 |

## 关键设计决定

**台词是唯一真源。** `compile_storyboard.py` 把台词写进 `narration` 与 `text`，
无台词镜次两者都留空——不拿画面描述去填。那样会把短剧变成解说。
画面描述只进 `visual` 字段，那是给质检看的，不是给旁白念的。

**光影归属场景母图。** 上游红线 2 禁止分镜层描述光影，因此
`compile_image_jobs.py` 把场景主视图（`3xx`）作为独立一层，
逐镜合成图以它为底再叠人物道具。光影只画一次，不会逐镜漂移。

**场景图不依赖人物参考图。** 场景主视图的规格是「无人、无道具」，
若挂上角色参考图，生图模型会把人物画进场景。

**`cw` 分组按场边界，不按固定镜数。** 渲染器自带的 `config:voiceover` 按
固定 3 镜一组切分，跨场连读会让配音把两个场景黏在一起。
场次切换才是天然的旁白停顿点。

**空白台词镜次保留 cue 槽位。** VTT 的 cue 数必须等于 `scene_ids` 数，
下游用这个等式把字幕和镜次一一绑定。空白台词镜次用零时长 cue 占位，
不能过滤掉——短剧里纯反应镜和空镜很常见。

**台词锁比对前剥离表演提示。** 剧本写 `舒十七：（不抬眼，竖起一指）第一，我不是大侠。`，
分镜面板写 `舒十七：第一，我不是大侠。`。比对时剥离 `（…）`，
但**不做标点归一化**——标点变了就是变了。

## 十条红线的落地

`verify_lock.py` 覆盖其中可机器化的九条：

| 红线 | 检查 | 级别 |
|---|---|---|
| 1 台词逐字一致 | 剧本 ↔ 分镜面板 ↔ storyboard.json 三处 | 阻断 |
| 2 禁光影色调词 | 画面描述与提示词，词级检测 + 普通词白名单 | 阻断 |
| 3 禁 BGM | 音效段不得出现音乐字样 | 阻断 |
| 4 台词不进提示词 | 出图提示词不得包含台词正文 | 阻断 |
| 5 单镜 ≤8s | `duration_sec` 上限 | 阻断 |
| 6 长台词拆镜 | 超过 20 字 | 阻断 |
| 6 台词念得完 | 低于 2 字/秒 | 警告 |
| 7/8 资产齐备 | 上场角色齐、每镜恰引一个场景 ID、无悬空 ID | 阻断 / 警告 |
| 9/10 资产 ID 区间 | 角色 1xx、道具 2xx、场景 3xx；角色道具禁衍生 | 阻断 |
| S7 track 唯一递增 | 全剧不按集重置 | 阻断 |

光影检测刻意分两级：多字词（`阴影`/`色温`/`逆光`）命中即违规；
单字（`光`/`影`）先剔除白名单（`电影`/`背影`/`目光`）再判定。
早期版本用单字直接判，会把「电影质感」和「目光」一起报上来。

## 已知上游缺陷

跑 `content/examples/中间人/` 会报出 8 项阻断，全部是示例自身的问题，
不是适配器的 bug：

- track 9/16/18/25 画面描述出现「袖影」「阴影」，违反红线 2
- track 10/11/12/24 台词 21–31 字，超过红线 6 的 20 字上限

这正是加这一层的目的：让上游示例自己的问题在进入渲染前暴露出来，
而不是变成一段画面与配音对不上的成片。
